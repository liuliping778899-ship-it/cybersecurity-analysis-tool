## Branch Naming Convention

The following branch names are used in this project:

- `development`
- `feature/log-analysis`
- `feature/vulnerability-scan`
- `feature/documentation`

Feature branches should use lowercase letters and hyphens.

## Commit Message Convention

Commit messages should be short, clear, and descriptive.

Examples:

- `feat: add failed login detection`
- `fix: handle invalid log entries`
- `docs: update project setup instructions`
- `test: add sample security data`

## Pull Request Process

1. Create a feature branch from `development`.
2. Complete and test the feature.
3. Push the feature branch to GitHub.
4. Create a pull request into `development`.
5. Add a detailed description.
6. Reference the related Freshservice ticket.
7. Review the changes.
8. Merge after testing is complete.

## Security Guidelines

- Do not upload real passwords.
- Do not upload private customer information.
- Do not upload access tokens or API keys.
- Use sample or anonymized security data.
- Validate program input.
- Document security findings clearly.
