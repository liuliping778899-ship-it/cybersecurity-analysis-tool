# Freshservice Issue Tracking Process

## Student Information

**Student Name:** Liping Liu  
**Project:** Cybersecurity Analysis Tool  
**Assignment Type:** Individual Project  

## Purpose

Freshservice was used to create, assign, update, and resolve cybersecurity issues during this project. GitHub was used to manage the related source code and documentation.

## Issue Workflow

The following ticket workflow was used:

1. Open
2. Pending
3. Resolved

The Pending status was used while the related feature was being developed and tested.

## Issue Creation

Each Freshservice ticket included:

- A clear subject
- A detailed description
- Requirements
- Expected results
- Priority
- Requester
- Assigned agent
- Current status
- Related GitHub branch

## Issue Assignment

All tickets were assigned to Liping Liu because this was an individual assignment.

## GitHub Commit References

GitHub commit messages referenced the related Freshservice ticket number.

Examples:

- `feat: detect repeated failed logins - Freshservice INC-4`
- `feat: add risky port assessment - Freshservice INC-5`
- `docs: document Freshservice issue tracking - Freshservice INC-6`

## Cybersecurity Tickets

### INC-4: Implement Failed Login Detection

This ticket tracked the development of the security log analysis feature. The script detects repeated failed login attempts and generates an alert for possible brute-force activity.

Related branch:

`feature/log-analysis`

### INC-5: Identify Risky Open Ports

This ticket tracked the development of the vulnerability assessment feature. The script identifies potentially risky ports and provides security recommendations.

Related branch:

`feature/vulnerability-scan`

### INC-6: Complete Project Documentation

This ticket tracked the creation and improvement of the project documentation.

Related branch:

`feature/documentation`

## Resolution Process

A ticket was marked as Resolved after:

1. The related work was completed.
2. The files were tested or reviewed.
3. Clear GitHub commits were created.
4. A pull request was completed.
5. The changes were merged into the development branch.

## Security Guidelines

The project used sample data only. Real passwords, customer information, private IP addresses, access tokens, and API keys were not uploaded to GitHub.
